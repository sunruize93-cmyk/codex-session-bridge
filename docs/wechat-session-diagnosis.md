# 微信安全重登诊断

2026-10-22。目标是调查自动化期间出现的安全重登，不是把重复人工登录当作修复。**尚未证明解决原问题。**

## 已有证据

- 实际界面出现“为了你的账号安全，请重新登录”。用户在正常重新登录后又报告没有主动退出；不能归为用户关闭应用。
- 更新前出现安全重登时，微信主进程持续存在，版本 4.1.8 (37351)。安装包通过 codesign 的完整严格核验，保留 Apple Mac OS Application Signing 签名。该核验不证明账号状态正常，也不证明不存在其他运行时因素。
- 系统 AX、屏幕录制权限已生效；先前显式探测只得到窗口外框，没有聊天标题、编辑器或消息控件。
- 正式工具的一次聊天定位在前台核验阶段返回 FOCUS_LOST。源代码和合成测试确认这条失败分支在 AX 输入和点击之前返回；不能由此推断整场交互没有其他 UI 操作。
- 插件没有登录、退出登录、重启微信、客户端注入或凭据导出接口。没有发送、评论、发布或微信消息读取成功。
- 用户报告：完全手动使用时没有出现同样安全提示，仅在 Codex 操作时出现。这是用户提供的现象，不是平台给出的检测原因。
- 随后的对照仅使用窗口元数据与系统截图，没有前置、点击、键盘或微信 AX 访问。用户确认“一直保持登录”。本轮没有继续分离测试 AX 和输入各自的影响，不能确定具体触发点。
- 文件助手独立窗口在 WindowServer 中名称正确、微信前台，但 SharingState=0；ScreenCaptureKit 两种截图接口均得到全透明数据。合成图片的本地 Vision OCR 正常，不能把空结果归为 OCR 已成功读到聊天。

对照缩小了调查范围：这轮屏幕观察没有复现掉线，但账号/设备策略、客户端兼容性、AX 或输入行为的具体影响仍未区分。不能把“机器人检测”写成已证实根因，也不能由有限观察推导免重登保证。

## 本轮已修复

1. 通用 doctor 原来会遍历微信 AX 树，即使只检查浏览器。现在只读环境、进程和权限元数据，不创建微信 AX 应用对象；测试会在任何此类调用时直接失败。
2. 登录状态检查原来只认“登录”按钮，可能漏掉安全重登提示。现在识别模态容器内部的安全重登文案和确认按钮，背景聊天不能抵消阻断。
3. 消息区域的普通“登录”按钮不作为登录墙证据。裸窗口不再被标为可用会话。
4. 同一次检查缓存子树关系，避免为模态/消息区域分类再次访问应用 AX。发现 AUTH_REQUIRED 后停止，不自动点击确认、重新扫码或重试业务动作。
5. 新增显式 screen-readonly 后端，完全绕过本插件 AX 路由且不产生输入。绑定/检查仅看元数据；读取需要前台唯一独立聊天窗口、同帧 OCR 精确标题核对。最多返回 3 行文字并标明消息边界未验证；所有写接口在观察应用前拒绝。
6. 屏幕共享状态不是 readOnly 时，在截图之前返回 SCREEN_CAPTURE_RESTRICTED；共享正常但截图全透明则 SCREEN_CAPTURE_EMPTY。不会修改客户端/共享属性或自动回退 AX。

25 项 Python 合成测试通过（13 AX、12 屏幕）；34 项 TypeScript/MCP 测试通过。独立审查复现的模态漏报、消息按钮误报、聊天名内部空格混淆、分行重登提示漏报和主窗口标题误接纳均已修复。它们验证本地行为，不证明账号不再重登。

Apple 将 CGWindowSharingType.none 定义为窗口不共享；当前观测与全透明捕获一致。这是读屏受限的证据，不是安全重登根因的证据：[Apple 文档](https://developer.apple.com/documentation/coregraphics/cgwindowsharingtype/none)。

用户已明确授权官方更新及一次无 AX、无输入只读对照。现已从 4.1.8 更新并正常重启到 4.1.15（270135）；完整旧应用保留在本地忽略目录，不访问或迁移聊天数据。替换原 root 所有的应用需要 macOS 管理员授权，由用户本人在系统弹窗完成。

官方 DMG 的腾讯 Developer ID 为 5A4RE8SF68，SHA256 为 ceea355d5c93419658f777fdd1010f9b19d14fab6dc552af9c208cddad7f248f；复制后的暂存包及最终安装均通过 codesign 完整严格核验。初次复制省略扩展属性，导致个别组件失去签名属性，未安装该副本；重新完整保留属性后核验通过并安装。暂存包通过 Apple 公证，最终安装路径另做复核。来源：[微信 Mac 官网](https://mac.weixin.qq.com/)。

## 更新后的最后一次对照

- 更新后确认微信 4.1.15 运行；最终安装路径通过 Apple 公证复核。曾检测到前台文件助手独立窗口，其 SharingState 仍为 0。该元数据不证明新版截图一定全透明，因为没有再次捕获。
- 初次正式屏幕绑定返回 SCREEN_TARGET_UNVERIFIED；随后只用元数据等待前台条件，超时未开始捕获或业务读取。
- 用户明确表示“这个是最后一次尝试”，并说明担心账号风险。按此边界又执行了最后一次屏幕绑定：仍为 SCREEN_TARGET_UNVERIFIED，截图 0、正文读取 0、AX 访问 0、点击/键盘输入 0；未创建有效绑定或读取任务。
- 该错误表示未能核验当前目标，不足以确定是前台、标题、窗口尺寸还是其他核验条件不满足。不能将其改写为截图成功、安全重登已解决或账号不受影响。
- 最后一次后停止所有微信观察与控制，不再等待/探测窗口、切换后端、读取 AX、重试登录或请求用户再次配合。后续只整理已有脱敏证据。

## 未完成的验证

- 用户已提供手动使用和屏幕观察的定性对照，但没有持续时长、事件分母或日志，不能计算发生率。
- 新版窗口仍标记不可共享，最后绑定未通过目标核验，微信消息读取仍为 0。升级安装成功；读取能力和安全重登修复均未证明。
- 原因调查按用户最后一次的限制结束；本轮不再操作真实微信账号，也不继续请求人工前置或登录。
- 如果仍由平台要求认证，保留 AUTH_REQUIRED 并停止。不能靠随机轨迹、轮换账号/网络、修改客户端或自动重新登录来声称解决。

仓库只保留脱敏状态和合成样本，不包含账号标识、聊天正文、实测笔记正文、Cookie 或原始截图。
