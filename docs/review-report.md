复核新增修复：异步哈希后同步重查账号/遮罩；prepare 快照不再作为结果确认依据，改为提交调用内捕获专属回执；取消与恢复交叉时保留取消；重复未知恢复不增加代次；忘记正文使用事务与删除墓碑，旧内存对象不得恢复正文。上述路径均补回归。

## 本机安装与只读验收后的复核

独立适配器审查发现并复现了以下问题，主实现者先加入失败测试，再修复：

- 新版搜索框的普通提交按钮缺失时，回退全局控件可能误点 AI 按钮。现代容器现在只接受其内部唯一可用提交按钮；原探针返回 UI_CHANGED，AI 点击为零。
- 旧结果的 outerHTML 仅因点赞数、图片加载或属性变化就被判为新结果。现在比较笔记 ID 和标题语义，噪声变化保持 pending。
- 背景聊天控件抵消安全重登模态层，仍可能点击聊天。现在按模态容器自身证据阻断；原探针 AUTH_REQUIRED、点击零。
- 消息区的普通“登录”按钮误报会话失效。现在排除消息子树，原探针不再误报。

另外补充双重关键词编码、同一卡片链接消歧/外站拒绝、正文延迟挂载、doctor 不创建微信 AX 对象的回归。

屏幕只读后端另经独立审查：修复聊天名内部空格混淆、重登提示分行导致漏报，以及主窗口标题被当作独立聊天。现在拒绝主窗口保留标题、同名多个窗口、非前台目标及 sharing0/unknown；受限状态在捕获前停止。prepare/dispatch/reconcile 在任何观察前拒绝，屏幕路由测试禁止导入 ApplicationServices。合计 34 项 TypeScript/MCP 与 25 项 Python 测试。审查不操作实机、不读取用户状态或实测内容。微信安全重登根因仍未确诊；代码复核通过不是免重登证明。

剩余风险：真实平台 DOM、AX 和账号身份可观测性；固定版本升级需重新验证；本地用户进程属于信任边界；本地去重不等于平台端 exactly-once。详见 compatibility.md 与 validation-report.md。

两名既有审查代理仅离线读取新代码、运行 jsdom / fake Unix socket 探针；未调用真实浏览器、doctor、微信工作者，也不读取真实账号的 artifacts。

| 反例                                            | 修复及证据                                                                                |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 默认 doctor 在只测浏览器时仍启动微信工作者      | 默认过滤微信，须显式 channel；默认/IG 及跨渠道流程的微信 spy 调用为 0                     |
